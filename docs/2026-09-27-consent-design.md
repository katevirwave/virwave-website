Status: reviewed candidate, not deployed in this record. Website branch: `codex/mcp-account-connect`. Parent owns preview verification and production promotion through the existing Vercel integration; the older GitHub Pages hosting notes do not describe this deployment.

The consent card contains the original VirWave logo, a left-aligned assistant heading, a compact account identity, two breathing-purpose rows, plain-language requested permissions, and a prominent account-access warning. Explicit age/privacy declarations remain unchecked. Allow connection is primary; Cancel is secondary. Both paths retain the existing authorization behavior.

Unknown client names are rendered as text with an identification warning; unknown scopes remain visible with a conservative explanation. Missing details do not imply email access or identify a host. Known email/offline-access permissions use independently reviewed plain language. Residual account/profile/sign-in access remains visible without a disclosure control.

The frontend-design and ui-ux-pro-max skills informed the single-column hierarchy. VirWave's existing navy/mint tokens and system font override generic palette and font suggestions. Focus moves to the heading while scrolling the full card top into view so the logo remains visible. No new imagery, fonts, dependencies, authentication protocol, production configuration, research choices, or marketing settings were added. Research invitations and marketing preferences belong in a separate account-settings flow with actual persistence; they must not be invented as consent checkboxes here.
